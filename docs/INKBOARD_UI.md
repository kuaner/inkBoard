# InkBoard UI 规范

这份规范是 InkBoard 的视觉与交互基线。它服务于一块长期显示的 Android 墨水屏：画面要像一张安静的编辑版面，信息有明确层级，触控后不会留下大面积状态残影。

## 核心气质

- 黑白、高对比、克制。界面使用纸张、黑墨、深灰线条和极少量浅灰块，不使用渐变、阴影、模糊和半透明浮层。
- 杂志式构图。每个页面只有一个明确标题、一个上下文标识和一组主操作；留白负责分组，不用说明性废话填满空间。
- 静态优先。页面不依赖连续动画、自动轮播、滚动列表或拖拽反馈；状态变化应通过一次清晰的局部刷新完成。
- 触控友好。文字链接也必须有足够的点击热区；返回按钮、翻页按钮和主要操作不做成难以命中的小图标。

## 版式

- 横屏是主版式，页面左右留白使用约 `44dp`；竖屏使用约 `22dp`。
- 页面顶部为统一页眉：左侧品牌或返回，中央/左侧为页面标题，右侧为短标签或动作。
- 主页顶部导航保持单层：`SYSTEM EPD`、`SENDER`、`APPS`、`MENU`。高频入口放在主页，不藏进二级菜单。
- 主页内容遵循“英雄内容 + 应用网格”：时间/主句占据视觉中心，下方是固定的 4 × 2 应用区域。
- 分割线只用于真正的结构边界，必须与两侧内容共用同一条基线；不要为了装饰再套一层外框。

## 文字

- 正文和操作文字使用接近黑色的实色，重要文字使用粗体或黑体；禁止用难以辨认的浅灰承载关键信息。
- 英文短标签使用大写、适度字距；中文标题保持自然字距，不堆叠无意义的产品口号。
- 一页只保留用户做决定所需的说明。状态文字要直接说“服务已开启”“正在加载”“保存失败”，不要写抽象的产品宣言。

## 控件

- 黑色块只表示主操作或当前明确选中项，不能把每次点击都变成大面积黑底刷新。
- 普通选项使用纸色底 + 黑色细边框；选中或强调项使用黑底白字。不要用大面积浅灰填色，墨水屏上会显脏。
- 不使用阴影、圆角卡片堆叠和 Material 弹窗。需要编辑时使用整页面板，离开后再应用可能触发系统刷新的设置。
- 加载状态保留页面骨架和翻页控件，只替换状态文字；不要用空白页或旋转进度动画让控件消失。

## 墨水屏行为

- 应用抽屉和图标选择使用手动翻页，不使用连续滚动。
- 全刷只能由明确的“全刷”操作或系统策略触发；普通导航不主动制造全屏刷新。
- 点击后不做涟漪、缩放和过渡动画。静态页面的黑白变化越少，残影越可控。
- 需要展示错误时使用页面内高对比文字，不使用黑底 Toast；错误信息应留在当前上下文中，便于判断下一步。

## SENDER

SENDER 是主页一级入口，不放在 `MENU` 里。进入后启动临时 HTTP 服务，返回 InkBoard 时关闭服务，不使用常驻 Service。

- 平板页只展示三件事：服务标题、连接模块、如何结束服务；连接模块把浏览器地址、端口、状态和二维码放在同一个黑白块面中。二维码不使用额外边框，保留纯黑白模块和足够的静区，避免在墨水屏上形成孤立的装饰框。
- 电脑网页先选择平板的目标保存目录，默认是 `Download/InkBoard`，也可以选择已发现的公共目录或输入一个自定义相对目录；目录穿越和 `Android` 受保护目录由服务端拒绝。
- 网页同时支持“选择文件”和“选择文件夹”。选择文件夹时使用浏览器的目录选择能力，并将 `webkitRelativePath` 作为目标目录下的相对目录传给平板。
- 文件按固定大小分片上传；当前默认分片为 `8 MB`，单片失败自动重试。平板端只在临时目录随机写入分片，全部分片完成后才发布到 `Download/InkBoard`，避免半个大文件出现在用户目录。
- 目录结构只允许在目标目录下创建，服务端清理路径分隔符、控制字符和 `..`，防止目录穿越。
- 网页上的进度用单行文字表达，不使用持续动画；上传完成后提醒用户返回平板关闭服务。

## 命名

- 系统级刷新策略统一叫 `SYSTEM EPD`，避免使用用户无法理解的 `DEFAULT` 作为主页入口。
- 页面标题与入口一致，使用短的英文名加句点，例如 `SYSTEM EPD.`、`SENDER.`、`MENU.`、`APPS.`；说明文字使用中文解释实际作用。
